My approach is deliberately simple:

**understand the problem → design the system → build the smallest useful version → test it → improve it.**

I'm currently interested in the space where **AI meets real software engineering** — intelligent applications, vision systems, automation, data-driven products and scalable application architecture.

## 04 / HOW I THINK

<br>

<table width="100%">
<tr>

<td width="50%" valign="top">

### I DON'T START WITH CODE.

I start with questions.

```text
What is the actual problem?

What does the user need?

What constraints exist?

What happens at scale?

What can fail?

What is the simplest useful solution?
```

</td>

<td width="50%" valign="top">

### THEN I BUILD THE LOOP.

```text
┌──────────────┐
│   PROBLEM    │
└──────┬───────┘
       ↓
┌──────────────┐
│   MODEL      │
└──────┬───────┘
       ↓
┌──────────────┐
│  ARCHITECT   │
└──────┬───────┘
       ↓
┌──────────────┐
│    BUILD     │
└──────┬───────┘
       ↓
┌──────────────┐
│ TEST / DEBUG │
└──────┬───────┘
       ↓
┌──────────────┐
│   ITERATE    │
└──────────────┘
```

</td>

</tr>
</table>
